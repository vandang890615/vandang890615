### О себе

**Ван Данг (Van Dang)** — инженер-строитель (металлоконструкции) и разработчик систем САПР/ТИМ.

Специализация — тяжёлые промышленные конструкции и инженерное программное обеспечение:
- **Проектирование металлоконструкций:** Расчёт и рабочая документация (КМ/КМД) по нормам AISC, Eurocode и TCVN; параметрическое трёхмерное моделирование строительных конструкций, расчёт узловых соединений и подготовка файлов ЧПУ для заводского раскроя.
- **Разработка САПР/ТИМ:** Разработка компонентов САПР и ТИМ с открытым исходным кодом на **Rust** и **Python** ([SolidCraft](https://github.com/tangency-labs/solidcraft), [IngeTrazo](https://github.com/ingelibre/ingetrazo), [OpenCADStudio](https://github.com/HakanSeven12/OpenCADStudio)), создание легковесного движка САПР на платформе **.NET 10** ([VNCAD](https://github.com/vandang890615/vncad)), автоматизация проектирования через протокол **MCP**.
- **Инженерная автоматизация:** Системы диспетчеризации цехового производства металлоконструкций, обработка ведомостей расхода материалов (BOM), скрипты на AutoLISP и Python.

### 🚰 Инженерная философия: Ментальная модель «Трубопровода» (The Pipeline Mental Model)

> *«Инженер-строитель организует физические магистрали для функционирования объекта; инженер-программист проектирует конвейеры данных, приводящие в движение цифровой мир.»*

<details>
<summary><b>Русский: Всё в IT — это просто «Система трубопроводов»</b></summary>
<br/>

Мой профессиональный путь начался в проектировании строительных конструкций промышленных объектов. Проектируя системное ПО, я осознал, что применяю ровно те же принципы: доставку «жидкости» из пункта А в пункт Б с заданным расходом, давлением, без утечек и с запорной арматурой на случай аварий. Разница лишь в том, что теперь эта жидкость — данные.

#### 🗺️ Сопоставление физических инженерных сетей и системной разработки

| 🏠 Физическая инфраструктура (Промплощадка / Трубопровод) | 💻 Эквивалент в программной инженерии | ⚙️ Практическая реализация в проектах |
| :--- | :--- | :--- |
| **Вода, газ, технологические среды** | **Данные (байты, векторы, токены)** | Базовая субстанция, циркулирующая в памяти и потоках исполнения. |
| **Внутренняя разводка здания** | **Локальный канал (`stdio`, IPC, Shared RAM)** | Прямой обмен командами между **MCP-серверами** и САПР-платформами (SolidCraft, VNCAD, IngeTrazo) с нулевой задержкой. |
| **Городские магистральные сети** | **Сетевые протоколы (HTTP, WebSockets)** | Распределённая синхронизация между цехом металлоконструкций и центральным сервером. |
| **Бронированные усиленные трубы** | **Защищённые туннели (SSH, VPN, TLS/HTTPS)** | Шифрование конфиденциальных чертежей КМД и карт раскроя ЧПУ. |
| **Регулирующая арматура и фильтры** | **API Gateway и конвейеры валидации** | Проверка целостности топологии перед геометрическими расчётами. |
| **Непрерывный поток из крана** | **Потоки данных (`Readable` / `Writable`)** | Потоковая загрузка тяжелых BIM-моделей и спецификаций Tekla частями (chunk) без переполнения RAM. |

#### 🔧 Трубопроводам необходимо линейное оборудование

Трубы лишь транспортируют. Надёжная магистраль требует распределённого линейного оборудования:

| 🏠 Оборудование на трассе (Промплощадка / Цех) | 💻 Эквивалент в архитектуре ПО | ⚙️ Практический пример на производстве |
| :--- | :--- | :--- |
| **Резервуары и накопители** | **Базы данных, постоянное хранилище** | База данных Master BOM, складской учёт металлопроката, график цеха. |
| **Насосные агрегаты** | **Процессоры CPU/GPU, вычислительные воркеры** | Процессы статического расчёта и автоматической калькуляции объёмов. |
| **Демпферные емкости (гидроаккумуляторы)** | **Очереди сообщений, буферы (Queue/Buffer)** | Очередь файлов чертежей на обработку для защиты от пиковых перегрузок. |
| **Расходомеры и датчики потока** | **Мониторинг, телеметрия, логирование** | Контроль пропускной способности и выявление узких мест в реальном времени. |
| **Обратные клапаны** | **Ограничение частоты запросов (Rate Limiting)** | Защита от обратного тока данных и шторма запросов на входной порт. |
| **Предохранительные клапаны** | **Паттерн автоматического отключения (Circuit Breaker)** | Автоматическая изоляция сбойного узла во избежание каскадного падения системы. |

#### 📐 Перевод абстрактных терминов в физические параметры
* **Протокол (Protocol):** *Резьбовые соединения и фланцы.* Оба конца трубы должны иметь идентичный шаг резьбы и диаметр (JSON-RPC, REST, gRPC), чтобы исключить утечку данных.
* **Пропускная способность (Bandwidth):** *Диаметр сечения трубы.* Чем шире труба, тем больший объём мегабайт чертежей прокачивается в секунду.
* **Задержка (Latency):** *Физическая длина трассы.* Время, необходимое первой капле данных для прохождения трассы через промежуточные узлы.
* **Обратное давление (Backpressure):** *Гидравлическое сопротивление.* Когда потребитель не успевает, давление передаётся источнику для снижения скорости потока — защита RAM от переполнения при работе с тяжелыми BIM-моделями.
* **Утечки и засоры:** Утечка памяти (*Memory Leak*) — незаметная течь в трубе; взаимная блокировка (*Deadlock*) — два закрытых клапана, бесконечно ждущих друг друга.
* **🧬 Наследие философии Unix и MCP:** В 1970-х создатели UNIX придумали символ вертикальной черты `|` (Pipe operator) — прямое перенаправление вывода `stdout` на вход `stdin`. Сегодня открытый протокол **Model Context Protocol (MCP)** через `stdio` — это буквально труба Unix: сообщения JSON-RPC циркулируют между AI-агентом и САПР через стандартные потоки `stdin`/`stdout`.

> *🎯 Вывод: Инженеру-строителю незачем исследовать каждую отдельную молекулу жидкости. Ему важно управлять давлением, расходом, соединениями, клапанами и резервуарами. Архитектура программ устроена точно так же: понимая топологию потоков, любая сложная система становится предельно ясной.*
